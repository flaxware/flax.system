Exhibit F // architecture
REF // FLX-ARCH-02

Defense in depth

No single layer is trusted to hold. The design assumes each boundary can fail and makes sure the next one still stands.

Hardened kernel

A kernel configured to reduce attack surface before any user software runs.

Containers

Process and filesystem separation so that one compromised service does not expose the rest.

Sandboxes

Restricted environments for applications that handle untrusted content.

Influences

The architecture draws on several established privacy and security distributions.

  • Qubes OS: compartmentalisation by virtual machine
  • Tails: amnesic, Tor-routed live systems
  • Whonix: isolated gateway and workstation design
  • Kodachi: privacy-focused, hardened live environment
  • Parrot OS: security-oriented and privacy-aware workflow

Exhibit H // operating philosophy
REF // FLX-PHI-05

How the system is used

Small, consistent conventions reduce friction. Each one below is a deliberate choice.

Keyboard mappings

Modifier keys are assigned consistently across the desktop.

  • Super Launcher and workspace control
  • Menu Context actions
  • Meta System-level commands
  • Uni Character and symbol input

System conventions

  • /etc as registry: configuration lives in plain files that can be read, versioned, and backed up.
  • top as default monitor: process inspection uses the familiar terminal tool with no extra daemon.
  • 50-command Bash history: a bounded history keeps recall fast and limits what is stored on disk.
$ top
Default monitor. No additional daemon required.
$ ls /etc
Configuration is stored as plain text under /etc.
